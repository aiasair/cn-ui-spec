# 精简界面说明

## 严格克制界面说明

**默认不添加说明。相信用户能理解清晰的名称、内容和操作。页面标题、菜单、按钮、区块、卡片、标签页和普通表单项，不得惯例性地搭配解释小字。**本规则约束的是不必要的解释，不只是字号；把说明放大、换颜色或藏进提示气泡，不能规避本规则。

### 禁止的默认做法

- 标题下面自动补一行“在这里，您可以……”或概述本页已有功能；区块、卡片下面重复其名称含义。
- 菜单或标签页附一行功能解释；按钮下面再写点击后的显然结果，或给文字按钮加重复其名称的 Tooltip。
- 给每个字段、开关或选项都配帮助文字，用“请选择”“点击即可”“支持便捷管理”等套话填满界面。
- 为填补留白、显得专业、展示功能丰富，添加副标题、宣传口号、英文眉题、功能清单、常驻提示条或新手教学。
- 把工程实现、内部流程或 AI 的设计理由写给产品用户，例如“基于某框架”“采用某布局”“此处用于展示……”。

名称不清楚时，优先改名称、按钮动词或信息组织；不能用一段说明补救含糊的界面。必要条件能直接写入名称时，优先使用“导出 CSV”等明确标签。

### 仅保留完成任务必需的信息

新增或保留一段说明前，必须能指出：**删掉后，用户会缺少哪项无法从名称、内容或当前状态得知的必要信息，进而无法完成任务或容易作出错误决定？**不能给出具体答案就删除。对“可能有帮助”“用户也许不懂”的泛泛推测不构成例外。

允许的窄范围情形包括：不显然的输入格式或限制、真实错误与恢复方式、禁用操作的具体原因、费用或权限影响、不可逆操作后果，以及当前任务明确要求的专业概念解释或教学引导。只在相关位置与时机，用最短且具体的文字表达；这些情形不是给所有控件批量添加说明的许可。必要信息仍须遵守规则一的可读性要求，不得一律缩成 12px。

有明确需要的进阶帮助可按需展开，但不要把本应删除的重复文案批量移入问号、Tooltip、折叠区或弹窗。影响当前决定的必要信息应在决定前可见。

本规则不要求删除文章正文、AI 回答、商品或资源的实质内容、用于区分项目的必要摘要、时间与数量等有效数据，也不要求删去无障碍名称。它们不能被当作不必要的界面解释一并清空。

### 取舍示例与验收

| 界面内容 | 处理 |
| --- | --- |
| “项目管理”下写“在这里管理您的所有项目” | 删除说明 |
| “保存”按钮下写“点击保存当前设置” | 删除说明 |
| “导出”旁写“点击后导出 CSV 文件” | 按钮改为“导出 CSV”，删除说明 |
| 上传控件旁写“仅支持 CSV，最大 10 MB” | 限制确实存在且无法从控件得知时保留 |
| 删除确认中写“删除后无法恢复” | 确实不可恢复时保留 |

设计和验收时逐处检查标题下方、导航、卡片、按钮、字段帮助、提示气泡与空状态：删除重复名称、复述显然操作、无信息量的欢迎语和装饰性解释。空状态只表达真实状态与必要下一步，不附赠功能介绍。对保留的说明使用上述必要性判断；不要为证明合规而把判断理由再显示到产品界面中。
