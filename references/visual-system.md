# 视觉与布局体系

汉界通过内容关系与语义 Token 定义视觉规则，不指定第三方设计库、品牌色、图标产品或框架 API。默认值服务于具体场景，可记录合理的局部覆盖，不把示例颜色或尺寸宣称为普遍标准。

## 布局、对齐与阅读宽度

- 在项目中统一栅格、内容最大宽度、对齐线、工具栏位置与响应式断点，避免逐页自行决定。按内容和设备选断点，不把 767px 等示例值视为唯一标准。
- 中文标签与普通文本优先左对齐；统计值及表格数字优先右对齐，并在金额、百分比等场景使用一致小数位和适用的等宽数字。
- 中文连续阅读区域初始可按约 32–40 个汉字宽设计，并随字体、屏幕和内容验证；不是所有页面统一固定宽度，窄屏不得为凑字符数横向溢出。
- 卡片间距推荐 16px、内边距 16–24px、页面模块间距 24–32px、桌面左右留白 24–32px；图标与文字默认间距 8px。大幅展示留白可登记 64px Token。
- 标题与说明是否存在先服从精简说明规则；导航、卡片、统计组和阅读段落按不同内容关系组织，不把所有页面都拼成重复卡片。

## 组件尺寸与形状

单行文字、普通按钮、表格、菜单、输入框的完整高度及间距见[行高与间距](spacing.md)，不重复维护。另补充：

| 属性 | 建议基线 |
| --- | --- |
| 大按钮 | 44–48px 高 |
| 小圆角／常规圆角／卡片圆角 | 4／8／12px |
| 普通边框 | 1px |
| 常用图标视觉尺寸 | 16／20／24px |
| 常用弹窗宽度 | 400／520／640px，按任务内容选择 |

以上为尺寸角色，不要求每个产品全部使用。组件基准高度不能成为多行或文字放大后的上限；窄屏弹窗必须受可用宽度约束，内容与操作均可触达。移动命中区域与图标或按钮的视觉尺寸分别设计，不能用小图标尺寸充当触控目标。

## 语义色与主题

- P1：颜色用语义角色管理，包含主色、成功、警告、危险、中性，以及相应文字、边框、填充、悬停、聚焦、选中、禁用变体；仅定义产品需要的状态。
- 品牌主色由项目品牌及实际可读性决定，不预置某组件库的品牌蓝或要求所有产品使用同一套视觉皮肤。文字灰阶参考与对比度要求见[字号规范](typography.md)。
- P1：不能只靠颜色表达错误、选择或重要状态；使用清晰标签、图形或其他可感知标识，仍不添加重复解释。
- 若提供深色主题，为文字、边框、图表、弹层与状态色分别设置并验证 Token，不能只反转颜色。没有暗色需求时不擅自新增主题功能。
- 背景变化、透明叠层、图片与渐变上的文字需检查实际背景；有语义 Token 不等于对比度自动合格。

## 图标、层级与动效

- 同项目图标统一视觉框、大小与描边风格，优先复用同一套资源；纯装饰图标不承担唯一语义，独立操作图标必须有可访问名称。
- 阴影与叠层顺序统一登记为 Token；下拉、提示、抽屉与对话框不能靠逐次追加任意 z-index 争夺层级。
- 动效统一时长、缓动及用途，以状态反馈和空间关系为目的；不为填补界面增加持续干扰。遵守系统减少动态效果偏好，保留必要状态反馈。

## Token 组织

字号、行高、间距、颜色、形状、阴影、层级和动效形成汉界语义角色；公共定义与组件状态统一复用。新建 Web Token 可使用 `--han-` 前缀，原生 App 用平台对应的类型化主题或资源；不要求已有项目迁移变量名。

区分基础值、语义角色与组件用途，业务组件消费语义或组件 Token，避免复制原始值。库或框架提供的是工程实现机制，不是汉界规则的上游来源；不建立库专属规范目录。Token 声明、已有第三方代码及明确局部例外不受“业务组件禁止新增硬编码”的机械误报影响。
