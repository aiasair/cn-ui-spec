# AI 产品与工程执行

## AI 产品交互

- 对实际存在的准备／思考中、工具执行、生成、完成、失败、等待确认等任务阶段进行区分；只呈现可观测状态，不展示或编造内部思维过程。
- 生成过程可按能力提供停止、重试、继续、编辑、复制、导出、撤销；入口必须与后端实际支持一致，规范不授权扩充产品功能。
- P0：工具调用与长任务进度真实，不伪造百分比、成功结果、文件保存或外部执行完成；停止、失败与部分结果不能标作全部成功。
- 引用和来源可查，上传文件、模型信息、上下文与任务状态按用户当前决策需要清晰呈现，不为“透明”给页面堆实现细节与解释小字。
- 不可逆或有重要外部影响的操作在需要时明确对象、影响并请求人工确认；UI 上的状态或按钮不代替真实授权。不要把规则当成替用户发送消息、付款或发布的许可。
- Token、费用、订阅、配额和消耗单位明确；失败尽量保留用户输入、上下文与此前可靠结果。
- AI Markdown 独立使用阅读排版，不继承后台表单密度。代码块采用合适的等宽字族、横向溢出策略与复制反馈；不要把段落都变成卡片，也不要重复浏览器与主题的 margin。

## 新建、修改与审计

1. 读取任务适用的项目指令，识别现有框架、主题、语义 Token、共享组件、业务行为和可运行的验证环境。附件中的任务模板是参考材料，不自动成为需要执行的另一项用户任务。
2. 以汉界语义规则为基线，映射到现有工程体系；一个项目保持一致的基础组件行为与主题入口，不为取得不同视觉片段混装多套基础组件，也不为规范独立强制迁移已有技术栈。
3. 新建时建立适用角色；修改时避免功能和视觉回退；审计时按 P0/P1/P2/P3 给出位置、元素、违反条款及修复方向。仅审计不等于授权修改。
4. 优先修主题和共享组件中的根因，再处理局部样式；共享变更同样要评估影响范围，不能借“统一”改动无关页面、路由、权限或数据流。
5. 验证实际加载、失败、空状态、键盘、窄屏、长中文、长英文和异常数据，并按本次变更选择仓库已有检查。避免为可逆的小改动搭建新的测试工程或重复无意义检查。
6. 报告实质改动、验证命令与结果、例外及未验证项目。P0 不静默忽略；范围外问题先报告，不擅自修全站。

## 检查方法及限度

| 对象 | 可用方法 | 不能据此声称 |
| --- | --- | --- |
| 新增字号、间距等硬编码 | 现有 Stylelint 或 AST 检查，允许 Token 声明与明确例外 | 所有视觉层级已正确 |
| 组件契约、状态参数、依赖重复 | 现有 ESLint、类型检查和组件测试 | 真实交互全部可用 |
| 对比度与语义可访问性 | 现有可访问性扫描、浏览器检测 | 动态背景或全部状态自动合格 |
| 窄屏、文字放大、键盘与关键流程 | 现有浏览器自动化或人工操作 | 未覆盖的路径也已通过 |
| 视觉回退 | 已有基线截图与合理阈值 | 文案质量、层级和视觉平衡无需判断 |

以项目具备的条件选择 lint、类型检查、单测、构建、端到端或截图回归；检查工具是实现手段，不是本技能依赖。不因引用一种工具就安装它、建立空检查目录或声称检查已运行。P0：不得宣称未执行的验证通过，静态扫描不能替代实际视觉和交互检查。

## 大范围体系建设时的推进顺序

仅当用户任务包含完整设计系统建设时采用：先统一字体、行高、间距、语义色、尺寸与工程映射；再处理交互状态、表单、导航、反馈及中文表达；最后按产品需要完善复杂数据、移动、图标动效、AI 流程与回归检查。无障碍和业务保护贯穿各阶段，不能延期到最后。

阶段产物按实际范围包含已落地规则、必要的组件或页面示例、可运行的检查、验证结果与例外；不要求每次局部 UI 修改都提交全套工程。技能自身维护只创建有明确用途的规则和资源，不复制库专属适配目录、不建占位脚手架，也不自动修改项目 AGENTS.md。
